# Draft Clinical Data Dictionary

## Purpose and status

This document defines a proposed, pseudonymous data contract for future OralLens clinical-evidence studies. It is an engineering draft for clinical, statistical, privacy, and site review. It is not a database migration, collection form, ethics approval, data-use agreement, or authorization to receive patient data.

The current Part 2 manifest remains unchanged. Its positive-only object-detection contract is appropriate for the existing development dataset but is not suitable for external clinical validation because it cannot explicitly represent plaque-negative, indeterminate, or unusable cases.

No clinical data should be entered against this dictionary until the [External validation protocol](EXTERNAL_VALIDATION_PROTOCOL.md), governance approvals, and site-specific minimum-necessary review are complete.

## Design principles

- use the patient as the primary independent sampling unit
- keep direct identifiers and re-identification keys outside the ML workspace
- represent negative, indeterminate, limited-quality, and unusable inputs explicitly
- preserve original assessor labels separately from adjudicated reference labels
- keep reference labels and model predictions in separate entities
- retain provenance, versions, exclusions, and corrections without rewriting history
- collect only fields justified by the intended use and statistical analysis plan
- isolate related patients, encounters, bursts, crops, and derived images across partitions
- use constrained vocabularies and validation rules instead of ambiguous free text

## Data zones

| Zone | Contents | Permitted location |
|---|---|---|
| Clinical identity zone | Direct identifiers and re-identification key | Site-controlled clinical system only |
| Pseudonymous study zone | Study IDs, approved clinical context, reference assessments | Approved study data system |
| ML development zone | Pseudonymous images, labels, release metadata | Approved protected ML storage; never git |
| Locked evaluation zone | External images and labels with restricted access | Independent custodian or access-controlled evaluation environment |
| Reporting zone | Aggregate results and approved de-identified examples | Approved reports and artifacts |

The repository, `backend/var`, ordinary ML run folders, and local demonstration upload flow are not approved clinical data systems.

## Conventions

- identifiers are opaque strings generated by the approved study identity service
- identifiers must not contain names, initials, medical-record numbers, email addresses, phone numbers, dates of birth, or meaningful site-local codes
- timestamps and exact dates are omitted or transformed unless the protocol justifies them
- enumerations are lowercase machine values; displayed labels may be localized separately
- `required` means required for an entity to enter a released dataset, not permission to collect the field
- null and empty string are not interchangeable
- every entity includes `schema_version`, `created_by_process`, and an integrity/audit reference in the implemented schema

## Entity relationships

```text
site
  patient
    encounter
      acquisition_session
        image
          quality_assessment
          assessor_assessment
            region_annotation
          adjudication
          model_prediction        # always separate from reference data

dataset_release
  release_membership -> image and partition
```

## Site entity

| Field | Type | Required | Validation and meaning |
|---|---|---:|---|
| `site_id` | opaque string | yes | Pseudonymous unique site identifier; no address in ML exports |
| `site_role` | enum | yes | `development`, `external_evaluation`, `prospective`, or another protocol-approved role |
| `jurisdiction_group` | controlled string | conditional | Generalized only to the level justified for governance/analysis |
| `care_setting` | controlled enum | yes | Protocol-defined setting such as dental clinic or supervised research setting |
| `site_protocol_version` | version string | yes | Acquisition/site-manual version in effect |
| `governance_approval_ref` | opaque reference | yes | Points to controlled approval records; contains no approval document or PHI |
| `active_from_period` | generalized period | conditional | Use only when temporal analysis requires it |
| `active_to_period` | generalized period | no | Supports controlled site closure/version transitions |

## Patient entity

| Field | Type | Required | Validation and meaning |
|---|---|---:|---|
| `patient_id` | opaque string | yes | Unique study patient; stable across encounters within the approved study |
| `site_id` | opaque string | yes | References `site.site_id` |
| `consent_or_waiver_category` | enum | yes | Protocol-approved category; not a copy of signed forms |
| `permitted_use_version` | version string | yes | Data-use scope applied to this record |
| `withdrawal_status` | enum | yes | `active`, `withdrawn_retain`, `withdrawn_remove`, or protocol-defined equivalent |
| `eligibility_status` | enum | yes | `eligible`, `ineligible`, `pending`, or `not_assessable` |
| `eligibility_reason_code` | controlled code | conditional | Required when not eligible; no free-text clinical narrative |
| `age_band` | controlled enum | conditional | Exact bands chosen through privacy and statistical review; no date of birth |
| `approved_sex_or_gender_field` | controlled enum | conditional | Include only if clinically/statistically justified and governance-approved |
| `approved_population_group_fields` | separate constrained fields | conditional | Never use an unrestricted demographics JSON dump |

Sensitive subgroup fields must be defined individually, justified in the analysis plan, protected against re-identification, and omitted when sample size cannot support responsible use.

| Field | Type | Required | Validation and meaning |
|---|---|---:|---|
| `image_id` | opaque string | yes | Globally unique study image identifier |
| `session_id` | opaque string | yes | References `acquisition_session.session_id` |
| `source_image_id` | opaque string or null | conditional | Parent for an approved crop/derived image; never crosses partitions |
| `burst_or_repeat_group_id` | opaque string or null | conditional | Groups near-duplicate captures |
| `view_code` | controlled enum | yes | Approved intraoral view |

| `orientation_code` | controlled enum | yes | Native orientation after approved normalization |
| `file_relative_path` | safe relative POSIX path | yes | No absolute path, traversal, drive prefix, or backslash |

| `width_px` | positive integer | yes | Decoded pixel width |

Image filenames and embedded metadata must be stripped or transformed under the approved de-identification procedure. The manifest path is never derived from a patient-provided filename.

## Assessor-assessment entity

One record represents one assessor's independent conclusion for one image or protocol-defined assessment unit.

| Field | Type | Required | Validation and meaning |
|---|---|---:|---|
| `assessment_id` | opaque string | yes | Unique original assessment |
| `image_id` | opaque string | yes | References `image.image_id` |
| `assessor_id` | opaque string | yes | Pseudonymous qualified assessor |
| `assessor_role` | controlled enum | yes | Training/qualification category |
| `rubric_version` | version string | yes | Target-definition version |
| `blinding_status` | enum | yes | Must confirm model/partition blinding for primary reference labels |
| `target_status` | enum | yes | `positive`, `negative`, `indeterminate`, `not_visible`, or `not_assessable` |
| `assessment_unit` | enum | yes | `patient`, `image`, `tooth`, `surface`, or `region` as defined by protocol |
| `tooth_code` | controlled code or null | conditional | Numbering standard fixed by protocol |
| `surface_code` | controlled code or null | conditional | Required for surface-level assessment |
| `assessor_certainty` | controlled ordinal | conditional | Human certainty, never a model probability |
| `confounder_codes` | controlled set | no | Approved hard-negative or contextual findings |
| `assessment_revision` | positive integer | yes | Preserves corrections without overwriting prior records |

A negative assessment is an explicit record with zero associated target regions. It is not inferred from a missing row. `Indeterminate`, `not_visible`, and `not_assessable` must never be converted to negative.

## Region-annotation entity

| Field | Type | Required | Validation and meaning |
|---|---|---:|---|
| `annotation_id` | opaque string | yes | Unique region annotation |
| `assessment_id` | opaque string | yes | References one original assessor assessment or adjudicated reference |
| `target_class` | controlled enum | yes | Versioned clinical target vocabulary |
| `geometry_type` | enum | yes | `box_xyxy`, `polygon`, or another protocol-approved representation |
| `coordinate_space` | enum | yes | `normalized` or `pixels`; one convention fixed per release |
| `x_min`, `y_min`, `x_max`, `y_max` | finite number | conditional | Required for boxes; strictly positive area and within image bounds |
| `polygon_points` | validated array | conditional | Required for polygons; non-self-invalidating per approved validator |
| `tooth_code` | controlled code or null | conditional | Required where target is tooth-linked |
| `surface_code` | controlled code or null | conditional | Required where surface localization is evaluated |
| `visibility_status` | enum | yes | `visible`, `partially_visible`, or rubric-defined value |
| `source_tool_version` | version string | yes | Annotation software and export contract |

The implemented schema must reject NaN, infinity, boundary escape, invalid polygon geometry, non-positive boxes, and geometry inconsistent with image dimensions. Any clipping or sanitization policy must be explicit, tolerance-bounded, logged, and tested.

|---|---|---:|---|

| `image_id` | opaque string | yes | References evaluated image |

| `prediction_id` | opaque string | yes | Unique predicted region |
| `predicted_class` | controlled enum | yes | Model output vocabulary |
| `detector_score` | finite number `[0,1]` | yes | Ranking/filtering score; not a clinical probability |

## Cross-entity validation rules

An implemented release validator must fail closed when:

- required identifiers are absent, malformed, duplicated, or referentially inconsistent
- any direct identifier or prohibited metadata is detected
- an image path is absolute, escapes its controlled root, uses unsafe segments, or resolves through a prohibited symlink
- a file is missing, undecodable, of an unsupported format, or fails its integrity hash
- a positive localized reference lacks valid region geometry
- a negative reference has a target region
- an indeterminate or not-assessable record is encoded as negative
- assessor labels are overwritten by adjudication
- a patient, encounter, source image, crop, burst, repeat, or near-duplicate crosses partitions
- calibration or external-test labels appear in a development export
- an exclusion lacks a structured reason
- a release lacks immutable schema, rubric, license/use, and provenance versions

Warnings that do not invalidate a release must still be structured, counted, and reviewed; they must not silently alter source records.

## Minimum release audit

Each candidate release must report:

- unique patients, encounters, sessions, native images, and derived images
- counts by partition, site, device, operator role, view, quality, target status, and approved subgroup
- explicit positive, negative, indeterminate, unsupported, and excluded counts
- assessor agreement, adjudication rate, and rubric version
- exact and near-duplicate results
- patient/encounter/related-image/site leakage results
- missing fields, invalid coordinates, path failures, and integrity failures
- permissions, license, retention, and permitted-use versions
- manifest and file-integrity hashes

No aggregate count alone proves clinical representativeness or adequate sample size.

## Relationship to the current Part 2 manifest

| Current Part 2 field | Future concept | Important difference |
|---|---|---|
| `sample_id` | `image_id` | Future image IDs belong to a governed identity hierarchy |
| `patient_id` | `patient_id` | Future ID is pseudonymous and linked only in the clinical identity zone |
| `split` | `partition_role` | Future roles separate calibration, external test, and prospective cohorts |
| `image_relative_path` | `file_relative_path` | Same safe-relative-path principle, plus de-identification/integrity metadata |
| `source_csv_line` | provenance/audit reference | Future provenance is versioned across site, acquisition, assessor, and release entities |
| `annotation_count` | explicit status plus region count | Zero regions is valid only with an explicit negative or non-evaluable status |
| `annotations_json` | assessor and region entities | Original labels, adjudication, clinical units, and model predictions remain separate |

The future schema should be implemented as a new versioned contract after clinical/statistical approval. The current loader must not be loosened to accept future negatives as an incidental side effect.

## Required review and sign-off

- dental clinical lead: target vocabulary, assessment units, confounders, quality rubric, and reference standard
- biostatistician: analysis fields, sampling units, subgroup variables, missingness, and partition roles
- privacy/data-governance owner: minimum necessary fields, de-identification, access, retention, and permitted uses
- site owner: capture feasibility, source-system mapping, and identity separation
- ML owner: machine validation, provenance, leakage detection, immutable releases, and prediction isolation
